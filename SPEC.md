## 1. Цель

Инструмент для врача по рентгенэндоваскулярной хирургии: планирование TEVAR, EVAR и FEVAR/BEVAR по КТ-ангиографии. Ориентир по удобству и точности — 3mensio Vascular (только по функциональности, без копирования и реверс-инжиниринга).

Целевая скорость: от загрузки исследования до готового отчёта — 10–15 минут на типичный случай.

Ключевые функции:

1. Полуавтоматическая центральная линия аорты и ветвей по нескольким кликам.
2. Синхронные виды: выпрямленная CPR, перпендикулярный срез, 3D.
3. Автоматический контур просвета и полуавтоматический контур наружной стенки на срезе; диаметры и площади.
4. Автоматический поиск и маркировка устьев ветвей: расстояние вдоль центральной линии, часовое положение, диаметр, угол отхождения.
5. Углы С-дуги.
6. Отчёт в виде sizing sheet.
7. Экспорт полой модели аорты с ветвями (открытая трубка) в STL для 3D-печати.

## 2. Ограничения и принципы

- **Только для исследовательского использования.** Это не медицинское изделие. В окне программы и в каждом отчёте — пометка «Только для исследований. Не для принятия клинических решений».
- **Данные пациентов.** Никогда не открывай, не читай и не анализируй содержимое реальных исследований пациентов. Работай только с папками `data/phantoms/` (синтетические фантомы) и `data/public/` (публичные обезличенные наборы, которые я положу сам). Реальные исследования я проверяю сам локально.
- **Платформа:** Windows 10/11 x64, последняя стабильная версия 3D Slicer 5.x. Всё должно работать без сборки Slicer из исходников; кастомная сборка — только опциональный последний этап.
- **Железо:** обычный ПК с дискретной видеокартой. Типичная КТА — 512×512×(500–1500) срезов, шаг 0.5–1 мм.
- **Автоматика предлагает, врач подтверждает.** Каждое автоматическое действие имеет ручную коррекцию.
- Все числа выводятся с единицами: длины в мм, углы в градусах, площади в мм².

## 3. Архитектура

Главный принцип: вся «хирургическая» математика живёт в отдельной Python-библиотеке, не зависящей от Slicer. Slicer — только оболочка: загрузка, отображение, взаимодействие и вызов ядра. Это нужно, чтобы позже можно было перенести ядро в отдельное приложение.

```
aortaplan/
├── CLAUDE.md
├── SPEC.md                    # этот файл
├── PROGRESS.md
├── README.md                  # установка и запуск
├── core/
│   ├── aortaplan_core/        # БЕЗ import slicer / qt / ctk
│   │   ├── geometry/          # кривые, rotation-minimizing frame, проекции, длины
│   │   ├── centerline/        # обработка центральных линий, разбиение на ветви
│   │   ├── crosssection/      # контуры, диаметры (Feret, по площади, по периметру)
│   │   ├── ostia/             # поиск устьев, часовое положение, углы отхождения
│   │   ├── carm/              # углы С-дуги
│   │   ├── sizing/            # шаблоны EVAR/FEVAR/TEVAR, oversizing
│   │   ├── printing/          # полая модель, обрезка, проверка герметичности
│   │   ├── report/            # HTML/PDF/CSV/JSON
│   │   └── phantoms/          # генератор синтетических фантомов
│   └── tests/                 # pytest, запуск обычным Python вне Slicer
├── slicer_extension/
│   └── AortaPlan/
│       ├── AortaPlan.py       # главный модуль: мастер шагов, режим приложения
│       ├── Resources/UI/      # .ui файлы
│       └── Testing/           # тесты внутри Slicer
├── scripts/                   # запуск тестов, установка зависимостей
├── validation/                # сравнение с 3mensio
└── data/
    ├── phantoms/
    └── public/
```

Правила:

- Ядро работает с numpy-массивами и `vtkPolyData`/`vtkImageData`. Входы и выходы — простые dataclasses, сериализуемые в JSON.
- Зависимости ядра: numpy, scipy, vtk. SimpleITK или scikit-image — только если реально нужны. Любую новую тяжёлую зависимость сначала согласуй со мной.
- Внутри Slicer зависимости ставятся через `slicer.util.pip_install` с проверкой при старте модуля.
- Расширения Slicer: SlicerVMTK (Extract Centerline и др.), SegmentEditorExtraEffects. Расширение Sandbox — только если нужной функции CPR нет в ядре Slicer (проверь). При старте модуль проверяет наличие расширений и понятно сообщает, чего не хватает.
- Подключение модуля при разработке — через Additional module paths; опиши в README.

## 4. Соглашения о координатах и измерениях

### Системы координат
- Slicer работает в RAS, DICOM — в LPS. Ядро работает в RAS, в миллиметрах. Конверсия — только на границе, покрыта тестами.
- Ориентация пациента для часов и углов берётся из геометрии изображения, а не из «верха экрана».

### Часовое положение устья (по умолчанию, настраивается)
- Плоскость — перпендикулярный срез аорты в точке устья.
- 12:00 — передняя стенка (проекция направления Anterior на плоскость среза).
- 3:00 — левая сторона пациента, 9:00 — правая (как на аксиальном срезе в радиологической ориентации, вид со стороны ног).
- Вывод: ч:мм (шаг не грубее 15 мин), градусы 0–360 по часовой, мм дуги по окружности графта заданного диаметра: L = угол / 360 · π · D.
- Проверка здравого смысла на нормальной анатомии: чревный ствол и ВБА ≈ 12:00, левая почечная ≈ 3:00, правая почечная ≈ 9:00 (±1–2 часа).
- В дуге аорты направление Anterior почти параллельно оси, и привязка вырождается. Поэтому нужен rotation-minimizing (parallel transport) frame, протянутый от нисходящей аорты, и/или привязка 12:00 к большой кривизне. Режим выбирается в настройках, в отчёте указывается, какой использован. Проверь, какой frame уже вычисляет `vtkMRMLMarkupsCurveNode`; при необходимости реализуй свой в ядре.

### Длины
- Вдоль центральной линии — основная величина.
- Вдоль большой и малой кривизны: линии строятся по точкам контура стенки на каждом срезе в направлении от центра кривизны и к нему.
- Прямое расстояние между точками — только как дополнительная величина.

### Диаметры на срезе
- Минимальный и максимальный (Feret, rotating calipers), средний, по площади 2√(A/π), по периметру P/π, площадь, периметр.
- Каждая метрика считается и по просвету (inner-to-inner), и по наружной стенке (outer-to-outer).

### Углы С-дуги
- LAO/RAO — вращение вокруг продольной оси пациента; LAO — детектор смещён к левой стороне пациента.
- CRAN/CAUD — наклон; CRAN — детектор смещён к голове.
- Перед реализацией явно опиши в коде принятую математическую конвенцию (направление луча источник→детектор, знаки). Покрой её тестами на известных геометриях: AP = 0°/0°, LAO 90° = детектор слева от пациента и т.д.

## 5. Интерфейс

### Режим приложения
- Модуль включает «режим AortaPlan»: скрывает меню, тулбары, панель выбора модулей, Data Probe, Python-консоль и прочие элементы стандартного интерфейса Slicer, оставляя только своё.
- Переключатель «Показать интерфейс Slicer» — для отладки.

### Раскладка видов (custom layout)
- Большое окно — выпрямленная CPR; плоскость CPR можно вращать вокруг оси на 0–360°.
- Перпендикулярный срез в текущей точке центральной линии.
- 3D: полупрозрачный просвет, центральная линия, маркеры, устья.
- Опционально — аксиальный срез.

### Синхронизация
- Колесо мыши или ползунок двигает текущую точку по центральной линии; срез, курсор на CPR и в 3D обновляются вместе.
- Клик на CPR или по центральной линии в 3D переносит срез в эту точку.

### Мастер шагов (левая панель)
1. Исследование → 2. Центральная линия → 3. Измерения → 4. Устья → 5. Углы С-дуги → 6. Отчёт → 7. 3D-печать.
Можно вернуться на любой шаг.

### Прочее
- Пресеты окна/уровня: КТА, кальций, мягкие ткани, кость.
- Горячие клавиши для частых действий: поставить маркер, следующая/предыдущая точка, повернуть CPR.
- Стиль сдержанный, без декоративных элементов; крупные читаемые числа рядом с изображениями.

## 6. Функциональные требования

### 6.1 Загрузка исследования
- Импорт папки DICOM через стандартную DICOM-базу Slicer.
- Список только КТ-серий с числом срезов и толщиной среза.
- Предупреждения: толщина среза > 1.5 мм, анизотропные воксели, gantry tilt.
- Опция анонимизации данных в отчёте.

### 6.2 Просвет и центральная линия
Подход «клики → путь», без обязательной ИИ-сегментации.

1. Пользователь ставит точку старта (например, восходящая аорта) и конечные точки (например, обе ОБА/НПА; для TEVAR — по желанию подключичные и сонные).
2. Диапазон HU контраста оценивается автоматически по окрестностям точек.
3. Просвет выделяется наращиванием области от точек в этом диапазоне внутри ROI. Защита от протекания в позвоночник и кости:
   - морфологическое размыкание тонких мостиков;
   - опциональная маска костей как маска исключения (например, позвонки и рёбра из TotalSegmentator, только если он установлен, — не обязательная зависимость);
   - «стоп-точки», которые ставит пользователь.
4. Минимальный набор ручной правки без открытия полного Segment Editor: кисть, ластик, ножницы.
5. Центральная линия — Extract Centerline (SlicerVMTK) с заданными конечными точками, со сглаживанием. Результат — сеть кривых: основной путь (аорта → подвздошные) и ветви.
6. Добавление ветви: клик в просвет ветви → достраивание ветви до этой точки.
7. Ручная правка центральной линии перетаскиванием контрольных точек.

Альтернатива на случай, если подход выше окажется ненадёжным: путь минимальной стоимости (fast marching по карте интенсивности или «сосудистости») прямо между точками. На этапе 2 оцени оба варианта на фантомах и публичных данных, выбери и объясни выбор.

### 6.3 Измерения на срезах
- Контур просвета строится автоматически как пересечение сегментации с плоскостью среза и редактируется как замкнутая кривая с контрольными точками.
- Контур наружной стенки (стенка + тромб) — полуавтоматический: лучи из центра просвета, поиск границы по профилю HU, затем ручная правка. Это критично: графт подбирают по наружной стенке.
- Все метрики из раздела 4 на каждом срезе; график диаметров вдоль всей центральной линии.
- Именованные маркеры на центральной линии: готовый список («Проксимальная зона посадки», «Нижняя почечная», «Бифуркация», «LSA», «LCCA» и т.д.) плюс свои названия. Таблица расстояний между любыми маркерами.
- Автопоиск максимального диаметра аневризмы на выбранном участке.
- Для EVAR: углы шейки α (супраренальная ось — ось шейки) и β (ось шейки — ось аневризмы); индекс извитости подвздошных (длина по центральной линии / прямое расстояние).
- Для TEVAR: зоны Ishimaru 0–4 по найденным устьям, диаметры в зонах, расстояния между устьями ветвей дуги.

### 6.4 Устья ветвей
- Для каждой ветви из сети центральных линий найти точку, где её центральная линия выходит за поверхность просвета аорты; это центр устья.
- Автоматическая маркировка по эвристикам: порядок вдоль оси и направление (передние — чревный ствол, ВБА; боковые — почечные; в дуге — БЦС, ЛОСА, ЛПКА). Всегда с подтверждением или переименованием пользователем.
- Ручное добавление устья кликом на срезе.
- Для каждого устья:
  - название;
  - расстояние вдоль центральной линии от выбранного опорного маркера и между соседними устьями;
  - часовое положение (ч:мм, градусы, мм дуги для заданного диаметра графта);
  - диаметр ветви на заданном расстоянии от устья (по умолчанию 5 мм);
  - угол отхождения (краниокаудальный и аксиальный компоненты);
  - стеноз устья — только ручная отметка.
- Добавочные почечные и другие мелкие ветви ≥ 2–3 мм не теряются, если пользователь их отметил.

### 6.5 Углы С-дуги
- Для маркера на центральной линии: все перпендикулярные проекции в виде кривой LAO/RAO против CRAN/CAUD и проекция из этого множества, ближайшая к AP.
- Для устья: проекция «в профиль» — луч перпендикулярен плоскости, содержащей ось аорты и ось ветви.
- Вывод: график и числа в отчёте.

### 6.6 Отчёт
- Шаблоны: EVAR, FEVAR/BEVAR, TEVAR.
- Содержимое: все измерения выше, таблица устьев, доступы (минимальный диаметр НПА/ОБА с каждой стороны, извитость, кальциноз — ручная отметка).
- Подсказка диаметра графта по oversizing (настраивается, по умолчанию 10–20 %) — только как ориентир.
- Скриншоты CPR и срезов в ключевых маркерах.
- Экспорт: HTML (с печатью в PDF), CSV и JSON. JSON полностью восстанавливает измерения.
- Пометка «Только для исследований».

### 6.7 Модель для 3D-печати
- Из сегментации просвета с ветвями строится полая трубка: стенка заданной толщины (по умолчанию 1.5 мм) наружу от просвета.
- Ветви обрезаются на заданной длине от устья (по умолчанию 15 мм).
- Все концы срезаются плоскостями, перпендикулярными центральной линии, — получается открытая трубка.
- Сглаживание не должно заметно менять диаметры: на фантоме изменение < 0.2 мм.
- Проверка перед экспортом: модель замкнута (watertight), без non-manifold рёбер, одна связная компонента. Если нет — понятное сообщение и попытка исправления.
- Экспорт STL в миллиметрах. Опция «сплошной просвет» для литья силиконовых моделей.
- По возможности использовать Hollow (SegmentEditorExtraEffects) и Plane cut (Dynamic Modeler); если надёжнее — своя реализация в ядре на VTK.

### 6.8 Сохранение
- Сессия сохраняется как сцена Slicer (.mrb) плюс JSON с измерениями, маркерами, устьями и настройками. Повторное открытие восстанавливает всё.
- Отмена последних действий как минимум для маркеров, устьев и правок контуров.

## 8. Этапы разработки и критерии приёмки

**Этап 0. Каркас.**
Репозиторий со структурой из раздела 3, `CLAUDE.md`, `PROGRESS.md`, `README.md`, git. Пустой модуль AortaPlan загружается в Slicer; режим приложения включается и выключается. pytest для ядра. Скрипт запуска тестов внутри Slicer без окна (проверь флаги командной строки Slicer, например `--no-main-window` и `--python-script`). Генератор фантомов с первыми тестами.
*Приёмка:* все тесты запускаются одной командой; README описывает установку.

**Этап 1. Оболочка.**
Загрузка DICOM, раскладка видов, мастер шагов, пресеты окна/уровня, синхронизация срезов вдоль произвольной (пока вручную нарисованной) кривой.
*Приёмка:* на публичной КТА (проверь, есть ли абдоминальная КТА в Sample Data Slicer) виды синхронно движутся вдоль кривой.

**Этап 2. Просвет и центральная линия.**
*Приёмка:* на фантомах отклонение центральной линии от истинной ≤ 0.5 мм в среднем и ≤ 1 мм максимум; на публичной КТА путь от восходящей аорты до обеих подвздошных строится без ручной правки или с минимальной.

**Этап 3. CPR и перпендикулярный срез.**
*Приёмка:* CPR вращается вокруг оси; клик на CPR, срез и 3D согласованы; точка на CPR корректно переводится в координаты исходного объёма (тест).

**Этап 4. Измерения на срезах.**
*Приёмка:* на фантомах (круг, эллипс, аневризма с «тромбом») ошибка min/max/среднего диаметра ≤ 0.3 мм при вокселе 0.7 мм; длины вдоль оси — ошибка ≤ 1 мм.

**Этап 5. Устья.**
*Приёмка:* на фантоме с ветвями на известных расстояниях и часах ошибка часового положения ≤ 5°, расстояний ≤ 1 мм; найдены все ветви ≥ 3 мм.

**Этап 6. Углы С-дуги.**
*Приёмка:* тесты на известных геометриях проходят; результаты совпадают с ручным расчётом.

**Этап 7. Отчёт.**
*Приёмка:* HTML/PDF/CSV/JSON генерируются; JSON полностью восстанавливает измерения.

**Этап 8. 3D-печать.**
*Приёмка:* STL фантома замкнут, толщина стенки ±0.2 мм, открытые концы перпендикулярны оси.

**Этап 9. Сохранение сессии и отмена действий.**

**Этап 10. Инструменты валидации.**

## 9. Тестирование

Генератор синтетических фантомов в `core/aortaplan_core/phantoms` сохраняет объём (NRRD) и JSON с истинными значениями:

- прямая трубка известного диаметра;
- изогнутая трубка (тор, спираль) — проверка длин и frame;
- эллиптическое сечение;
- веретенообразная аневризма с «тромбом» другой плотности — проверка наружного контура;
- аорта с ветвями под заданными углами, на заданных расстояниях и часах (чревный ствол, ВБА, почечные);
- дуга с тремя ветвями;
- шум и частичный объём (размытие), кальцинаты у стенки, «кость» рядом с аортой — проверка защиты от протекания.

Тесты ядра запускаются вне Slicer (pytest); интеграционные — внутри Slicer без окна.
