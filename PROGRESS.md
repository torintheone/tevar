## Окружение

- Пользователь: Windows, 3D Slicer 5.12. Отдельный Python не нужен: тесты ядра можно запускать
  через `PythonSlicer.exe`. Git нужен, чтобы получать обновления (`git pull`).
- Claude работает в облачном Linux-контейнере без Slicer: download.slicer.org закрыт сетевой
  политикой. Здесь запускаются только тесты ядра; тесты внутри Slicer запускает пользователь.
  GitHub Actions гоняет тесты ядра: Windows и Linux с Python 3.12, Windows с Python 3.9.

## Проверенные факты о Slicer (по исходникам тега v5.12.0)

- Slicer 5.12: Python 3.12.10, VTK 9.6 по умолчанию; main = 5.13 (preview). Slicer 5.8: Python 3.9.10.
- Флаги командной строки: `--no-main-window`, `--python-script`, `--no-splash`,
  `--additional-module-paths`, `--exit-after-startup`, `--disable-settings`, `--testing`.
  `--testing` не используем: он включает временные настройки, и установленные расширения не грузятся.
  Скрипт из `--python-script` выполняется после загрузки модулей; выход — `slicer.util.exit(code)`.
- При закрытии окна Slicer сначала выходит из текущего модуля, потом сохраняет состояние окна
  (`qSlicerMainWindow::closeEvent`). Поэтому режим AortaPlan восстанавливает интерфейс в `exit()`
  модуля — скрытые панели не попадут в сохранённые настройки.
- Модуль скриптового расширения добавляет свою папку в `sys.path` — `import AortaPlanLib` работает.
- scipy входит в поставку Slicer (SuperBuild `python-scipy`), numpy и vtk — тоже.
- Эффект **Hollow** — в стандартном Segment Editor (не в SegmentEditorExtraEffects).
- Модуля **Curved Planar Reformat** в ядре Slicer 5.12 нет (он в Sandbox) — решение на этапе 3.
- Dynamic Modeler (Plane cut) — в ядре Slicer; детали — на этапе 8.

## Этап 0. Каркас

### Сделано
- Структура репозитория по разделу 3 ТЗ (корень репозитория = корень проекта), `CLAUDE.md`,
  `PROGRESS.md`, `README.md`, `SPEC.md`, `.gitignore` (данные и объёмы в git не попадают).
- Ядро `core/aortaplan_core` (numpy, scipy, vtk; Python 3.9+):
  - `volume.py` — `ImageGeometry` (IJK→RAS, как IJKToRAS в Slicer) и `Volume` (массив `[k, j, i]`),
    трилинейная выборка по RAS;
  - `geometry/` — RAS↔LPS (только для границ), длины, ресэмплинг и касательные полилиний,
    rotation-minimizing frame (метод двойного отражения, Wang et al. 2008);
  - `fileio/nrrd.py` — свой читатель/писатель NRRD (LPS на диске, RAS в памяти; raw/gzip,
    отдельный файл данных, big-endian) — без новых зависимостей;
  - `vtk_bridge.py` — `Volume` ↔ `vtkImageData`, точки ↔ `vtkPolyData`;
  - `i18n.py` — все строки интерфейса и отчётов (ru по умолчанию, en);
  - пустые подпакеты `centerline`, `crosssection`, `ostia`, `carm`, `sizing`, `printing`, `report`.
- Генератор фантомов `core/aortaplan_core/phantoms`:
  - растеризация трубки по центральной линии с вложенными эллиптическими слоями, частичный объём
    (суперсэмплинг 4×4×4 граничных вокселей), размытие PSF и детерминированный шум;
  - сетка как у аксиальной КТ (IJK→LPS = единичная матрица), чтобы ошибки знаков проявлялись сразу;
  - фантомы: прямая трубка (в т.ч. косая на анизотропной сетке 0.7×0.7×1.25 мм и «реалистичная»
    с размытием и шумом), эллиптическое сечение, полутор (дуга в сагиттальной плоскости с ногами), спираль;
  - NRRD + `*.truth.json` (центральная линия, касательные, нормали, полуоси, аналитические
    диаметры/площадь/периметр, длины); CLI `python -m aortaplan_core.phantoms`.
- Модуль Slicer `slicer_extension/AortaPlan`:
  - пометка «Только для исследований…» в панели модуля и в заголовке окна в режиме AortaPlan;
  - «Режим AortaPlan»: скрывает меню, все тулбары (включая выбор модулей), строку состояния,
    Python-консоль, журнал ошибок, Data Probe, логотип, справку модуля, заголовок панели модулей;
    запоминает и точно восстанавливает исходное состояние; «Показать интерфейс Slicer» для отладки;
  - проверка окружения при открытии модуля: ядро, numpy/scipy/vtk, версия Slicer (рекомендуется 5.12),
    SlicerVMTK (модуль ExtractCenterline), SegmentEditorExtraEffects, TotalSegmentator (необязательно);
    установка недостающих Python-пакетов через `slicer.util.pip_install` с подтверждением;
  - `AortaPlanLib/bridge.py` — узел объёма ↔ `Volume` (объёмы под трансформом пока отклоняются).
- Тесты:
  - ядро: 63 теста pytest (координаты, геометрия сетки, кривые, RMF на прямой/окружности/спирали —
    сравнение с аналитическим кручением, NRRD, фантомы: площадь сечения ±0.5 %, положение стенки,
    длины, сохранение/загрузка, детерминированность шума; i18n; запрет `import slicer/qt/ctk/vtk`
    в ядре; скрипт запуска тестов с поддельным Slicer);
  - внутри Slicer (`Testing/AortaPlanSlicerTests.py`): модуль зарегистрирован, ядро импортируется,
    проверка окружения; NRRD ядра открывается Slicer с той же матрицей IJK→RAS и теми же вокселями;
    NRRD, сохранённый Slicer, читается ядром; мост узел↔Volume; режим приложения (только с окном).
- `scripts/run_tests.py` / `scripts\run_tests.bat` — все тесты одной командой; Slicer находится
  автоматически; отчёт тестов Slicer передаётся через JSON-файл; таймаут защищает от зависания.
- GitHub Actions (`.github/workflows/tests.yml`): тесты ядра на Windows и Linux, ruff.

### Отклонения от ТЗ и решения
- Строки интерфейса хранятся в `aortaplan_core/i18n.py`, а не в механизме переводов Slicer
  (`slicer.i18n` + Qt .ts): так одни и те же строки используются в интерфейсе и в отчётах ядра,
  и не нужны Qt-инструменты для компиляции переводов.
- Модуль не объявляет расширения в `dependencies`, а проверяет их при открытии: иначе без
  SlicerVMTK модуль вообще не загрузился бы и не смог бы объяснить, чего не хватает.
- Фантомы с аневризмой и «тромбом», ветвями, дугой с тремя ветвями, кальцинатами и «костью»
  добавляются на этапах 2, 4 и 5, где они нужны; инфраструктура (вложенные слои с переменными
  полуосями) уже есть.

### Известные ограничения
- Тесты внутри Slicer написаны по исходникам Slicer 5.12, но в контейнере не запускались.
- Заголовок окна в режиме AortaPlan может быть перезаписан, если Slicer сам изменит его (не нашёл
  такого кода в 5.12, но не проверено вживую). Пометка в панели модуля видна всегда.
- `run_tests.bat` без `SLICER_EXECUTABLE` находит Slicer только в папке по умолчанию
  (`%LOCALAPPDATA%\slicer.org`), а при нескольких версиях там может взять не самую новую
  (выбор по алфавиту). У пользователя Slicer стоит в `E:\Program\3D Slicer 5.12.4` —
  нужен `setx SLICER_EXECUTABLE ...` (описано в README).
- Растеризатор фантомов не оптимизирован: стандартный набор создаётся ~25 с.
