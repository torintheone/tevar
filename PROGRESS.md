## Окружение

- Пользователь: Windows, 3D Slicer 5.12. Отдельный Python не нужен: тесты ядра можно запускать
  через `PythonSlicer.exe`. Git нужен, чтобы получать обновления (`git pull`).
- Claude работает в облачном Linux-контейнере без Slicer: download.slicer.org закрыт сетевой
  политикой. Здесь запускаются только тесты ядра; тесты внутри Slicer запускает пользователь.
  GitHub Actions гоняет тесты ядра: Windows и Linux с Python 3.12, Windows с Python 3.9.

## Проверенные факты о Slicer (по исходникам тега v5.12.0)

- Slicer 5.12: Python 3.12.10, VTK 9.6 по умолчанию; main = 5.13 (preview). Slicer 5.8: Python 3.9.10.
- Флаги командной строки: `--no-main-window`, `--python-script`, `--no-splash`,
  `--additional-module-paths`, `--exit-after-startup`, `--disable-settings`, `--testing`.
  `--testing` не используем: он включает временные настройки, и установленные расширения не грузятся.
  Скрипт из `--python-script` выполняется после загрузки модулей; выход — `slicer.util.exit(code)`.
- При закрытии окна Slicer сначала выходит из текущего модуля, потом сохраняет состояние окна
  (`qSlicerMainWindow::closeEvent`). Поэтому режим AortaPlan восстанавливает интерфейс в `exit()`
  модуля — скрытые панели не попадут в сохранённые настройки.
- Модуль скриптового расширения добавляет свою папку в `sys.path` — `import AortaPlanLib` работает.
- scipy входит в поставку Slicer (SuperBuild `python-scipy`), numpy и vtk — тоже.
- Эффект **Hollow** — в стандартном Segment Editor (не в SegmentEditorExtraEffects).
- Модуля **Curved Planar Reformat** в ядре Slicer 5.12 нет (он в Sandbox) — решение на этапе 3.
- Dynamic Modeler (Plane cut) — в ядре Slicer; детали — на этапе 8.

### Известные ограничения
- Временная CPR — плоский срез через локальную касательную: при прокрутке он наклоняется вместе

- В дуге аорты ориентация перпендикулярного среза один раз скачком меняется на границе восходящей
  аорты и дуги (неизбежно для «передняя стенка вверху» в восходящей и нисходящей аорте одновременно).

- Список серий читает положения всех срезов каждой КТ-серии из базы DICOM: на очень большой базе
  открытие шага 1 может занять секунды.
- Текст в углу видов рисуется системным шрифтом (Arial/Segoe UI), иначе «мм» заменяется на «mm».
- Скорость ≥ 15 кадров/с проверяется автотестом только на фантоме; на реальной КТА — по чек-листу.
- Анонимизация в отчёте — на этапе 7.

## Этап 2. Просвет и центральная линия

### Как работает (как в 3mensio)
1. После выбора объёма в 3D включается объёмная реконструкция (пресет Slicer «CT-AAA»).
2. Шаг «Центральная линия»: «Начальная точка» → клик по аорте на 3D-реконструкции (Slicer 5.12 ставит
   точки прямо на объёмный рендеринг) или на срезе; «Конечные точки» → клики по подвздошным/бедренным
   (для TEVAR — и по ветвям дуги); при протекании — «Стоп-точки».
3. «Построить просвет и центральную линию» (индикатор прогресса с отменой):
   - диапазон HU: уровень контраста — 90-й процентиль вокселей < 700 HU в радиусе 6 мм от точек;
     нижний порог — середина между мягкими тканями (40 HU) и контрастом (уровень 50 % частичного
     объёма, граница совпадает со стенкой), верхний — уровень + 200 HU (кальций и кортикальная кость отсекаются);
   - точки сдвигаются в центр просвета (клик по 3D попадает на стенку), но не вдоль сосуда;
   - заливка в рамке вокруг точек; рамка расширяется (30 → 60 → 120 мм → весь объём), пока все
     конечные точки не соединятся с начальной (дуга аорты выходит за рамку вокруг точек);
   - защита от протекания: морфологическое размыкание (разрывает мостики в 1–2 вокселя), берутся только
     компоненты с точками, один шаг геодезического восстановления границы; стоп-точки вырезают шар 5 мм;
     маска исключения — любая сегментация (например, кости из TotalSegmentator, если он установлен);
   - сегментация «AortaPlan_Lumen» (полупрозрачная модель в 3D, контур на срезах);
   - центральная линия от начальной точки к каждой конечной; по пути — отдельная кривая разметки
     с контрольными точками через 8 мм (их можно тянуть мышью); выбор пути для навигации.
4. Правка: «Правка просвета» — встроенный Segment Editor только с кистью, ластиком и ножницами;
   «Перестроить линию по просвету»; «Добавить ветвь» — клик по ветви и автоматическое перестроение.
   Старая ручная кривая — в свёрнутом разделе «Ручная кривая».

### Сравнение двух способов построения линии (требование ТЗ)
- **Минимальный путь (ядро)**: путь минимальной стоимости 1/D² через просвет (D — расстояние до стенки,
  Дейкстра по графу вокселей), затем уточнение центра: в плоскости, перпендикулярной линии, 32 луча
  находят стенку по уровню 50 % (с интерполяцией) и центр берётся по окружности, вписанной по МНК;
  лучи, ушедшие в боковую ветвь, отбрасываются.
- **VMTK Extract Centerline**: по поверхности просвета (прореживание до 15 000 точек, шаг 0,5 мм).
- Измерено в контейнере (ядро, фантомы с шумом 15 HU и размытием 0,5 мм; допуск ТЗ: среднее ≤ 0,5 мм,

## Этап 3. CPR и перпендикулярный срез

### Решения (согласованы с пользователем)
- Пользователь спросил, не нужно ли три вида вместо двух. Принято: **две выпрямленные CPR под 90°**
  (как в 3mensio) + перпендикулярный срез + 3D; аксиальный срез — по галочке.
- CPR считается в ядре (без расширения Sandbox: модуля Curved Planar Reformat в ядре Slicer 5.12 нет).

### Сделано
- Ядро `centerline/cpr.py` — `StraightenedCpr`:
  - строки через 0,5 мм вдоль центральной линии (строка 0 — проксимальный конец), столбцы ±35 мм
    через 0,5 мм; поперечное направление переносится rotation-minimizing frame (без перекручивания
    в дуге), угол 0 — левая сторона пациента у проксимального конца (как корональный срез), 90° —
    передняя стенка для сосуда, идущего к ногам;
  - выборка трилинейная, ~15 мс на изображение 900 × 141 из объёма 512 × 512 × 600;
  - перевод CPR ↔ RAS: `to_ras(offset, s, angle)`, `from_ras` (точное обращение итерациями Ньютона,
    ошибка «туда-обратно» < 1e-5 мм), пиксель ↔ (смещение, мм вдоль линии), угол CPR через заданную точку.
- Slicer:
  - раскладка: CPR 1 и CPR 2 (угол + 90°) рядом слева, справа перпендикулярный срез и 3D
    (аксиальный по галочке); без центральной линии в этих окнах корональный, сагиттальный и аксиальный срезы;
  - изображения CPR — отдельные объёмы далеко над пациентом (ничто другое в этой плоскости
    не отображается); окно/уровень синхронизируется с исходным объёмом (пресеты, ручная настройка);
  - текущее положение — горизонтальная линия на обеих CPR; на перпендикулярном срезе две цветные
    линии показывают плоскости CPR 1 и CPR 2;
  - управление: в CPR левая кнопка тянет положение (клик — переход), колесо ±1 мм (Shift ±5 мм),
    Ctrl+колесо — поворот на ±5° (вместо масштаба; масштаб — правой кнопкой); окно/уровень левой
    кнопкой в CPR отключено (есть пресеты); перпендикулярный срез — как раньше.
- Тесты:
  - ядро: 122 теста (добавлены: прямая трубка в CPR — вертикальная полоса шириной 25 ± 1 мм
    под любым углом, поворот на 180° = зеркало, перевод туда-обратно на дуге, значение пикселя =
    значение объёма в переведённой точке, кальцинат находится в пикселе, куда переводится его центр);
  - внутри Slicer: изображения CPR совпадают с ядром при любом угле, линии положения и плоскостей,
    перевод пиксель вида → (смещение, мм) → обратно, переход по клику; с окном — перетаскивание
    в CPR, колесо и Ctrl+колесо, раскладка с тремя срезами.

### Проверено в контейнере
- Тесты ядра, ruff; логика навигатора с CPR прогнана на заглушках Slicer (рабочая папка, не репозиторий).

### Известные ограничения
- Свойство любой выпрямленной CPR: на внутренней стороне изгиба с радиусом меньше полуширины (35 мм)
  поперечные линии пересекаются («складка»), на очень извитых сосудах там возможны искажения.
- CPR перестраивается при каждом изменении угла или правке линии (~15 мс на изображение);
  при перетаскивании точки центральной линии обновляется на каждом шаге.
- Толщина CPR — 0 (без MIP/усреднения); слой с толщиной — по запросу.

### Доработки по замечаниям пользователя (версия 0.3.1)
Пользователь попросил: менять окна местами мышью; в режиме просмотра вернуть синхронизацию срезов
и линии перекрестья, «как в RadiAnt»; вращать CPR вокруг своей оси.
- **Раскладка**: окна меняются местами перетаскиванием за цветной заголовок окна на другое окно
  (фильтр событий на заголовке окна; переставляется порядок окон в описании раскладки, Slicer
  перерисовывает её на месте); три шаблона («Две CPR рядом», «Сетка 2 × 2», «Первое окно крупно»)
  и «Сбросить»; выбор запоминается в настройках Slicer. Одна раскладка вместо двух (с аксиальным
  срезом и без): аксиальный срез — пятое окно, включается галочкой.
- **Режим MPR (как в RadiAnt)**: аксиальный, корональный и сагиттальный срезы через общую точку,
  видимые и интерактивные линии пересечения (тянуть центр — сдвиг, линии — поворот, косые MPR);
  клик переносит остальные срезы в точку (`JumpAllSlices`, со смещением); Shift + движение —
  перекрестие Slicer, как обычно; левая кнопка — окно/уровень, колесо — листание. Без центральной
  линии и при постановке точек — всегда MPR. Переход в MPR центрирует срезы на текущей точке линии.
- **Режим «Вдоль центральной линии»** — как раньше (линии пересечения и прыжок срезов выключены,
  чтобы срезы не уходили с линии).
- **Вращение CPR мышью**: на перпендикулярном срезе потяните цветную линию CPR 1 или CPR 2 —
  обе CPR поворачиваются так, чтобы линия шла за курсором (берётся ближайший к текущему из двух
  концов линии, изображение не «переворачивается»). Ctrl + колесо и ползунок остались.
- Аксиальный срез (если включён) в режиме «вдоль линии» следует за текущей точкой.
- Тесты внутри Slicer: шаблоны и перестановка окон (порядок в описании раскладки, запоминание),
  поиск окна под курсором при перетаскивании, MPR (линии пересечения, перекрестие, клик переносит
  корональный и сагиттальный срезы в точку), вращение перетаскиванием линии, переключение режимов;
  ядро: выбор конца линии без «переворота» (`nearest_line_angle`).


## Этап 4. Измерения на срезах (версия 0.4.0)

### Решения (план согласован с пользователем)
- **Контур просвета** строится не как «ступенчатое» пересечение маски сегментации с плоскостью
  (ошибка до ±0,35 мм из-за вокселей), а по тем же правилам, что и сегментация, но с субвоксельной
  точностью: 360 лучей из центра просвета, граница — уровень 50 % между мягкими тканями (40 HU) и
  уровнем контраста, измеренным в этом же срезе; луч останавливается и на кальцинате (контраст + 200 HU).
  После первого прохода лучи пускаются заново из центра контура.
- **Наружная стенка** (стенка + тромб): от границы просвета луч ищет уровень 50 % между стенкой/тромбом
  (40 HU) и жиром (−100 HU); если у края стоит кальцинированная бляшка — край самой бляшки (её 50 %);
  длинный яркий участок (кость) или отсутствие жира (соседний орган вплотную) — граница не найдена.
- **Регуляризация** (оба контура): лучи без границы и лучи далеко за устойчивой гладкой аппроксимацией
  (ряд Фурье до 4-й гармоники; уходы в устья ветвей, в соседний орган) отбрасываются вместе с 4° по краям,
  пропуски заполняются по аппроксимации, затем сглаживается только отклонение от неё (3°) — шум
  убирается, а форма (острые концы эллипса) не сплющивается.
- **Средний диаметр** = (мин. + макс. Feret) / 2, как в программах планирования EVAR (для эллипса —
  сумма полуосей). Мин./макс. — Feret (вращающиеся калиперы по выпуклой оболочке); площадь и периметр —
  по самому контуру; D по площади 2√(A/π), D по периметру P/π.
- **Маркеры** — точки на центральной линии (узел разметки, сохраняется со сценой); положение
  пересчитывается проекцией на текущий путь, поэтому маркеры переживают перестроение линии.
  Расстояние по центральной линии: по общему пути, а для маркеров на разных ветвях — через точку
  расхождения путей. По большой/малой кривизне: в каждом срезе (шаг 1 мм) направление к центру кривизны
  (сглаженная вторая производная линии; на прямых участках переносится с соседнего изогнутого), точка
  контура просвета в этом направлении — малая кривизна, в противоположном — большая.
- **EVAR**: оси — хорды между точками линии: супраренальная (20 мм выше нижней почечной → нижняя почечная),
  шейка (нижняя почечная → конец шейки), аневризма (конец шейки → бифуркация аорты); α и β — углы между
  ними (0° = прямая). Индекс извитости: длина по линии / прямое расстояние от бифуркации аорты до ОБА
  (маркер) или до конца пути.
- Зоны Ishimaru для TEVAR — после этапа 5 (нужны найденные устья ветвей дуги).

### Проверено в контейнере
- Тесты ядра, ruff, совместимость с Python 3.9 (vermin).
- Логика контроллера измерений прогнана на заглушках Slicer (рабочая папка, не репозиторий):

### Известные ограничения
- Контур строится лучами из центра: сильно невыпуклый просвет (полумесяц при пристеночном тромбе,
  расслоение) может потребовать ручной правки.
- Наружная стенка без жировой прослойки (НПВ, двенадцатиперстная кишка, позвоночник вплотную)
  дорисовывается по соседним участкам — проверяйте контур; уровни 40/−100 HU пока не настраиваются в интерфейсе.
- Расстояние между маркерами на разных ветвях идёт через точку расхождения путей; её положение зависит
  от того, насколько точно совпадают пути до развилки (у путей VMTK — практически точно).
- Линейка на CPR точна только вдоль и поперёк линии (CPR — выпрямленное изображение).
- Автоконтур при прокрутке появляется после короткой паузы (30 мс) — сама прокрутка не замедляется.
- Зоны Ishimaru и расстояния между устьями ветвей дуги — после этапа 5.
